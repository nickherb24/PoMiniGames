### What CI actually gates (`.github/workflows/deploy.yml`)

Only the **Unit** tier runs in CI — Integration/E2E need Azurite and Playwright and stay local via `test-all.ps1`. But the build job carries three further hard gates that are easy to trip without touching a test:

- **Stylesheet check** (`scripts/css-lint.ps1`, 2026-10-01; no build needed, run it after any scripted CSS edit): fails on a comment that contains `/*` or a declaration block, a `*/` outside a comment, or unbalanced braces. Those are the marks of a selector cut out together with the end of the comment above it, which leaves that comment open until the next one and every rule in between commented out. A prune on 2026-08-07 did that in `fx.css`, `glass.css` and `games.css`, and Fun Quiz showed bare browser buttons for eight weeks. Never quote the comment terminator inside a CSS comment: two notes about this damage did, and each closed itself in mid-sentence.
- **Trim audit**: the WASM client is published with `PublishTrimmed=true` + `EnableTrimAnalyzer`. Combined with `TreatWarningsAsErrors`, a single IL2xxx warning from new reflection-heavy code fails master. The host's own publish does not exercise this, so the analyzer only ever sees the client here. `src/PoMiniGames.Client/TrimmerRoots.xml` is the escape hatch.
- **WASM bundle-size budget**: the trimmed `_framework` output must stay ≤ 25 MB. The baseline was ≈ 20 MB, most of it the PoSurvive simulation engine shipping client-side; that game was removed on 2026-09-12, so measure before assuming the old figure.

The PoRacer format check is blocking; a missing `v*` tag at HEAD is a warning, not a failure (MinVer just stamps a pre-release). Deploy targets the `PoMiniGames` resource group and **discovers** the App Service name from it rather than hardcoding it — a resource rename can no longer silently 404 the deploy. It runs on F1, which cannot enable AlwaysOn, hence the prewarm loop before the smoke tests; `WEBSITE_RUN_FROM_PACKAGE=1` means the zip is mounted atomically.

## Test structure rules

- **100/50/25/25 rule**: *every* tier has its own ceiling — Unit 100, Integration 50, E2E-API 25, E2E-UI 25 — enforced by one shared assertion, `TierCeilingGuard` in `tests/Shared/`. Each tier declares a sealed, empty subclass of it naming its own ceiling (`TestCountCeilingTests`, `IntegrationTestCountCeilingTests`, `E2EApiTestCountCeilingTests`, `E2EUiTestCountCeilingTests`); the same reflection used to be copy-pasted into all four. It counts `[Fact]`/`[Theory]` **methods**, not discovered cases (`TheoryAttribute` derives from `FactAttribute`, so one probe catches both). When one trips, consolidate two facts into one theory or relocate to a cheaper tier — never raise the cap.
- Headroom is deliberately **not** recorded here. It rots on every commit, and the figure that used to sit in this line ("Unit 0 slots") was three audits stale and wrong in the alarming direction. Count it when you need it — `grep -rh "^\s*\[Fact\|^\s*\[Theory" tests/PoMiniGames.<Tier> --include=*.cs | wc -l` — or just run the guard test.
- All four ceilings are enforced by `scripts/test-ceilings.ps1` in CI without infrastructure. `test-all.ps1` reports discovered cases separately; TierCeilingGuard enforces method counts.
- Tiers, and there are exactly four: `PoMiniGames.Unit` (hermetic, no I/O) → `PoMiniGames.Integration` (Testcontainers Azurite) → `PoMiniGames.E2EAPI` (WebApplicationFactory HTTP contract) → `PoMiniGames.E2EUI` (Playwright; host runs under the "Test" environment). A fifth project, `tests/Shared` (`PoMiniGames.TestUtilities`), is a library the other four reference, not a tier.
- **There is no JavaScript test tier and no pre-commit hook.** This file used to describe a bUnit `PoMiniGames.Component` tier and a Vitest **SimJs** tier over `tests/PoEcosystem.Sim`, plus Husky.Net hooks running ESLint and Vitest on staged files. None of it exists — there is no `package.json`, no `vitest.config.js`, no `.husky/`, and no such test projects. The Component tier was retired 2026-09-11 (`scripts/test-all.ps1` still notes it) and the JS tooling went in b42fad4. Nothing runs on commit; run `dotnet format` yourself.
- **Any test that POSTs/PUTs/DELETEs `/api/*` must call `client.ArmAntiforgeryAsync()`** (`tests/Shared/AntiforgeryTestExtensions.cs`) or it gets a 403, not the status it asserts. Re-arm after a sign-in — the token is bound to identity claims. Antiforgery is deliberately NOT disabled for the Test environment.
- **`tests/Shared/TestBudgetGuard.cs` is the single source of truth for AI mocking.** Every fixture (Unit harness, Integration factory, E2E-API host, E2E-UI Kestrel host) applies `TestBudgetGuard.Overrides` before serving traffic, so the suite can never spend live tokens even when real keys sit in `appsettings.Development.json` or user-secrets. **Adding a new AI boundary means exactly one edit there** — the earlier inline-duplicated dictionaries drifted, which is how `IFaceAnalysisService` ended up unmocked.
- Without Docker, storage-backed tests fail with `connection refused (127.0.0.1:10002)`. That is the environment, not a regression — `docker compose up -d azurite` first. Integration/E2E tiers are slow (E2EAPI is ~13 min); prefer `--filter` while iterating.

## Architecture

Instant-play mini-games platform: .NET 10 Minimal API host that also serves the Blazor WebAssembly client (single origin, port 5080), with SignalR for real-time multiplayer and Azure Table Storage for persistence.

### Projects (`src/`)

- **PoMiniGames.API** — API host (assembly `PoMiniGames.API`, but `RootNamespace` is pinned to `PoMiniGames` — every file declares `namespace PoMiniGames.*` explicitly and new files must match). Vertical slice architecture: each feature lives in `Features/<Slice>` — Account, Auth, ConnectFive, Health, Integrity, Invites, Leaderboard, MatchHistory, PoBrawl, PoCabinet, PoCoupleQuiz, PoEcosystem, PoFunQuiz, PoJevArena, PoJoker, PoMarbleRace, PoRacer, PoSports, PoVoxelStrike, Shared, TicTacToe — containing its endpoints, hubs, and services. **Every HTTP route and SignalR hub is registered in exactly one place**: `Infrastructure/EndpointRouteExtensions.MapPoMiniGamesEndpoints()`. Auth is applied at the route-group boundary — leaderboard reads are anonymous, all game-data writes require auth; rate limits are declared per slice (policy names: `highscores`, `leaderboard-read`, `play-session`, `account-data`, `ai-generation`, `pocabinet`, `pojevarena`, `pojevarena-decide`, `client-errors`, `invites`, in `Infrastructure/RateLimitingExtensions`). The list used to name `infer` and `face-analysis`: `infer` guarded PoSurvive's relay and was deleted unused on 2026-09-13, and `face-analysis` never existed here at all — `IFaceAnalysisService` survives only in comments.
- **The `/api` prefix is declared once**, on the authenticated group: `app.MapGroup("/api").RequireAuthorization()`, with each slice mounting a *relative* group under it (`MapGroup("/joker")`, `MapGroup("/matches")`, …). It was `MapGroup("")` until 2026-09-11, with twenty-odd slice groups each repeating the literal `/api` — which hid the fact that this boundary is exactly the scope `AntiforgeryExtensions` validates. The anonymous surfaces (`MapGetLeaderboard`, `MapUnifiedLeaderboardEndpoints`, `MapPoVoxelStrikeAssetEndpoints`, `MapIntegrityStatusEndpoint`, and the platform/health/diag endpoints) are mapped on `app`, **not** on the group, so they still spell their full `/api/...` path. Getting that backwards silently relocates a route to the site root — `PlayerStatsEndpoints.MapGetLeaderboard` carries a comment saying so, because it is the one method in that file that differs from its three siblings.
- **Per-game notes live in `.claude/rules/<game>.md`, not in this file** (moved 2026-10-01; they were about 50 KB of it). Each is path-scoped by its `paths:` frontmatter, so it loads on its own when you open that game's files: the API slice, the client folder, `wwwroot/js/<game>/`, the Shared contracts or its tests. If you are about to change a game and its notes are not in context, read the file first — they record mirrored implementations and user calls the code alone does not show. Add new per-game facts there, not here.
  - `poecosystem.md` — observed, never steered (user call); the snapshot round-trip must stay deterministic; render frame stride is 16.
  - `pocabinet.md` — the physics is three mirrored sims (C#, JS, the lap verifier) on their own trig; 2 KB snapshot budget; lap proofs are regenerated, never hand-edited.
  - `pojevarena.md` — Jev is required, with no decision fallback; the server writes every word Jev sees; prompt wording is pinned by Verify snapshots.
  - `pomarblerace.md` — board totals are server-recomputed (a second copy of `game.js` `_resolve`); GLB map containment is derived at runtime from the collision shell.
  - `povoxelstrike.md` — wins are priced by a flag (two copies of the bonus); the interop argument order is a contract.
  - `sandplayground.md` — the shaders are strings `dotnet build` cannot check; three SUPPORT rules that look tunable are load-bearing.
  - `posports.md` — stored solo times are server-replayed from the key log; run proofs are regenerated, never hand-edited.
  - `poracer.md` — stored laps are the server's; the page pushes numbers, not objects; the race loop runs on wall time.
- Slice names do not map 1:1 to client games. `PoBrawl` and `PoMarbleRace` were both moved out of `Features.HighScores` so their namespaces match their own folders; don't reintroduce the split. PoSports' high-score endpoints live in `Features/PoSports/PoSportsHighScoresEndpoints.cs`. ConnectFive and TicTacToe have SignalR turn hubs in `Features/ConnectFive` and `Features/TicTacToe`; SandPlayground has no API slice and persists through shared PlayerStats/leaderboard endpoints, or not at all.
- **PoMiniGames.Client** — Blazor WASM client. Note the assembly/namespace is `PoMiniGamesClient` (csproj `PoMiniGamesClient.csproj`). Each game is a self-contained folder under `Games/` — fourteen of them: ConnectFive, PoBrawl, PoCabinet, PoCoupleQuiz, PoEcosystem, PoFunQuiz, PoJevArena, PoJoker, PoMarbleRace, PoRacer, PoSports, PoVoxelStrike, SandPlayground, TicTacToe — with its page, board/AI logic in C#. JS-heavy games (three.js/cannon-es) keep their engine code under `wwwroot/js/<game>/` — these files are served live from source in dev, no rebuild needed.
- **PoMiniGames.Infrastructure** — Table Storage access. `StorageService` + `HighScoreDescriptor<T>` implement a strategy pattern: one generic save/rank/get flow, one descriptor per game leaderboard. To add a leaderboard, write a descriptor; declare `RowKeyFields` explicitly (immutable identity fields only — usually the player, not the score) and use `ShouldOverwrite` to keep a better score from being clobbered.
- `StorageService` is **one class across three partial files**, split on the seam it already had: `StorageService.cs` (config, the availability probe, player stats, leaderboard, shared helpers), `StorageService.HighScores.cs` (the descriptors plus the single generic read/write they share), `StorageService.PoBrawl.cs` (the two accumulator boards below). It was a single 1,419-line file, the largest in the solution.
- **There is no in-memory storage fallback.** `InMemoryStorageService` was deleted on 2026-09-12 along with ~17 `if (_inMemoryFallback is not null)` branches. When Table Storage is unreachable, reads now return empty, writes are skipped, and the health check reports **Degraded** — the path `StorageService` already implemented for the null case. The fallback silently redirected every score into process memory, which on F1 (no AlwaysOn, so idle means recycle) meant they vanished minutes later; it duplicated, worse, the durability the client already has in `PendingScoreStore` + `ScoreSyncService`. Do not reintroduce it: a failed submit must stay failed so the client keeps and retries it.
- Two boards deliberately sit **outside** the descriptor pattern because they are accumulators rather than best-result ratchets, and a descriptor cannot express "move this value both ways": the PoBrawl presidents ladder, and the PoBrawl demo-mode fighter Elo (`PoBrawlFighterRatings` table). Both go straight through `TableConcurrency.UpdateWithRetryAsync`. The Elo board applies its rating change as an **increment**, never as an absolute computed from the read — increments commute, so two demo matches finishing at once compose instead of one clobbering the other.
- Client enums live in `Models/GameEnums.cs`; the separate `Enums/` folder was folded into `Models/` on 2026-09-13 (it held five enums while `Models/` held two more, for one concept in two namespaces), and `GameOutcome` was absorbed into `GameResult` at the same time — ConnectFive and TicTacToe each carried an identity switch to cross that seam. Client `Services/` is grouped into five folders, each its own namespace under `PoMiniGamesClient.Services.*`: `Auth/`, `Http/`, `Play/`, `Ui/`, `Interop/`. All five are in `_Imports.razor`, so `.razor` files need no using; a `.cs` file does. They were 31 loose files in one namespace — which, among other things, sorted the four-handler HTTP pipeline below into four unrelated alphabetical positions.
- **PoMiniGames.Shared** — models shared between client and server (game state DTOs, identity helpers). **PoMiniGames.Domain** — domain primitives and the storage contract (EloCalculator, GameKey, PlayerStats, `Abstractions/IStorageService`, `Models/LeaderboardDtos`).
- **There is no PoMiniGames.Application project** (dissolved 2026-09-13). It had shrunk to 110 lines in four files — `IStorageService`, `IDiagnosticsSnapshotProvider` and two DTO files — every one of which only used Domain types, while costing a csproj, a restore pass and a reference edge. The interfaces are now `Domain/Abstractions/`, the DTOs `Domain/Models/`. The API referenced Domain *through* it, so the API csproj now names Domain directly.
- **Two Elo systems, deliberately not unified.** `EloCalculator` rates a *player* against a fixed virtual AI rating per difficulty tier; because it depends only on accumulated win/loss/draw counts it is recomputable from scratch and safe to backfill. `PairwiseEloCalculator` rates *fighters* head-to-head for the PoBrawl demo board; each match is priced against the opponent's rating at that moment, so it is path-dependent and the stored value is the only record of the history. That difference is the reason there are two classes — don't merge them.
- Identity strings are hardcoded constants, never reflected from the assembly name: `TelemetryExtensions.CloudRoleName`, `PrefixKeyVaultSecretManager`'s secret prefix, and `DataProtectionExtensions.SetApplicationName("PoMiniGames")`. That last one keys the cookie key-ring purpose — deriving it from the assembly name would invalidate every live auth cookie on the next deploy. Keep them constant.
- Note `PoShared` still appears in the codebase meaning the **Azure resource group** and the Key Vault DNS name `kv-poshared`. It is not the project name; do not rename those.

### Cross-cutting facts

- Auth: Microsoft Entra (MSAL) with a BFF cookie pattern (`BffAuthenticationStateProvider`, encrypted cookies via Data Protection), plus a dev-only DevAuth bypass and guest login. Client gates most pages on auth.
- CSRF: `Infrastructure/AntiforgeryExtensions` validates a synchroniser token on every POST/PUT/PATCH/DELETE under `/api/*`. Scope is exact and load-bearing — SignalR hubs live at their own roots (`/poracer/lobby-hub`, …) so their POST `/negotiate` stays ungated, because the SignalR client cannot be taught to attach the header. `app.UseAntiforgery()` alone would NOT cover this app: since .NET 8 it auto-validates only form-bound endpoints, and every endpoint here takes JSON.
- The client `HttpClient` is an explicit four-deep handler pipeline built in `Client/Program.cs`, and **the order is a contract**: `TransientRetryHandler → AntiforgeryHandler → IncludeCredentialsHandler → HttpClientHandler`. Retry is outermost so every replayed clone re-enters `IncludeCredentialsHandler` and gets its credentials mode re-applied before hitting the browser transport; `AntiforgeryHandler` sits directly above `IncludeCredentialsHandler` because its token fetch must carry the cookie the server pairs the header against. A `window.fetch` patch (`js/crossOriginFetchPatch.js`) is a belt-and-braces duplicate of the credentials behaviour, scoped to the API origin only — a blanket patch previously broke MSAL sign-in.
- **AI (Azure AI Foundry)** — `src/PoMiniGames.API/AI/`, ~20 files, the most expensive thing to get wrong. One `PoMiniGames:AI` binding replaced the old per-game `*:AzureOpenAI:*` sections, resolved from Key Vault (`PoMiniGames--AI--FoundryEndpoint`, `--DefaultDeployment`, `--Deployments`). Chat clients compose as decorators: `BudgetedChatClient` → `ResilientChatClient` → `InstrumentedChatClient`. Spend is bounded by a per-identity daily ceiling (`TokenBudget:DailyTokensPerIdentity`, 250k), because a rate limit shapes burst but bounds no spend — one tab left open is ~36k calls/hour. (The `infer` policy that used to make this point is itself gone; `ai-generation` is the one that now fronts a model call.) `ValidateDeploymentsOnStartup` lists the account's real deployments and fails Production boot on a name that isn't there; that check exists because `gpt-4o-mini`/`gpt-4o` were configured for months and never existed on the shared account (real names: `gpt-5.4-nano`, `gpt-5-nano`, `gpt-5.4-mini`, `Phi-4-mini-instruct`, `Phi-4`). `AIFoundryOptions.Deployments` must stay a **plain settable `Dictionary`** — the configuration binder does not populate an `IDictionary` property through the indexer, and the silent failure was every game running on the default deployment while the status endpoint reported a different answer.
- **Concurrency is two-level, and the global level is the load-bearing one.** `AiConcurrencyGate` is a single `ConcurrencyLimiter` (2 permits) shared by every resilience pipeline; each pipeline *also* has its own small limiter for per-game fairness. Do not go back to one `AddConcurrencyLimiter` per pipeline: that builds a separate limiter each time, so the five registered pipelines permitted 10 concurrent calls against an account measured to serve one or two (`x-ratelimit-limit-requests: 1`). `GlobalQueueLimit` is computed from the partition count and must stay ≥ the sum of the per-game permits, or a call that won its game's permit gets rejected at the gate and the circuit breaker counts a healthy account as failing.
- **The token budget is durable.** `AiTokenBudget` is a write-behind cache over `IAiTokenLedgerStore` (Table `AiTokenLedger`, PartitionKey = UTC day, RowKey = identity hash), flushed every 30 s by `AiTokenBudgetFlushService` and once more on graceful shutdown. It was process-local, which on F1 (no AlwaysOn, so idle = recycle) made "250k per identity per day" mean "per identity per uptime". Writes are **increments under an ETag**, never absolutes — same reasoning as the PoBrawl demo Elo board. Call `CheckAsync`, not `Check`: only the async path hydrates an identity's durable total.
- **HybridCache has a real L2.** `TableDistributedCache` (Table `PoMiniGamesCache`, SHA-256 row keys, payload chunked across 64 KiB properties) is registered as `IDistributedCache` *before* `AddHybridCache()`. Without it the "L1/L2" was L1 only and every cached generation was re-bought after each recycle. It never throws — every failure degrades to a miss — and a failed table create is remembered for 10 s so a storage-down host does not pay the client's network timeout on every cache read.
- **Two providers, one SDK surface.** `PoMiniGames:AI:Provider` selects `azure` (Managed Identity) or `openai` (any OpenAI-compatible endpoint + `ApiKey`) — the latter reaches Ollama (`http://localhost:11434/v1`, free local dev) and Gemini's compatibility endpoint (cheaper per token, separate quota). Empty infers from the endpoint host, so existing Key Vault config keeps resolving to Azure. Both paths hand back the same `OpenAI.Chat.ChatClient`, so every decorator, the options cache and the capability table apply unchanged. `FoundryDeploymentValidator` skips non-Azure providers — it lists deployments from the Azure data plane and has nothing to call elsewhere. Pair a new provider with `ModelCapabilityOverrides`: the capability heuristic reads deployment names, and a local model's name rarely says what wire fields it accepts.
- **PoJoker is one model call per joke, not two.** The punchline prediction and the rating are a single structured reply (`VerdictSchema`, `punchline` declared first so it streams first), cached 24 h on the joke's content hash. Two concurrent calls against a 1-request account meant the second reliably ate a 429 plus a retry. The cost is that `joker.rating`'s cheap-deployment task key no longer applies to this path; round trips are the scarce resource here, not tokens. `QuizPrebakeService` (`PoMiniGames:AI:QuizPrebake:Enabled`, **off by default**) warms the PoFunQuiz question cache off-peak — it is the one background job that deliberately spends money, so it never switches itself on.
- **PoSurvive is gone (2026-09-12).** The game, its API slice (`Features/PoSurvive`: the `/api/infer` relay and `/api/evolution/*`), the `Inference:*` and `Simulation:*` configuration on both sides, the simulation engine in `Application`/`Shared`/`Domain` (`Application` has since been dissolved entirely — see above), the `survive` AI deployment key and its resilience partition, the `EvolutionRecords` table registration, and ~2 MB of `wwwroot` assets all went with it. `InferenceHealthTracker` stayed — it is general AI telemetry now, still in `PoMiniGames.Shared.Simulation.Models` because moving it would ripple through every chat-client decorator. The client takes `PoMiniGames.Domain` directly for the leaderboard row types.
- **Game routes are the uniform `/{game}/{mode}` scheme, with no aliases.** Modes are `1player` / `2player` / `multi` / `demo` (`GameModes.ToSlug`). The duplicate `@page` aliases were deleted on 2026-09-11 — `/funquiz/multiplayer` and `/{couplequiz,poracer,posports,povoxelstrike}/lobby` — and the matching `"multiplayer"` / `"lobby"` segments came out of `GameModes.Parse` with them. That pairing is load-bearing: three of those games also declare a `/{game}/{Mode}` catch-all, which would otherwise have swallowed the stale URL and parsed it as Multiplayer on a page that cannot host it. Unrecognised segments read as `OnePlayer`, which is what `Parse` already documented. Query-string legacy forms (`?mode=2p`, `?demo=1`) and the `2p`/`2ps`/`1` segments are still accepted — `2ps` in particular still drives PoFunQuiz split-screen.
- **Browser errors reach the server log (2026-10-01).** `js/errorReporter.js` posts uncaught errors, unhandled rejections, anything that hits `console.error` (which is where Blazor logs an unhandled component exception and where `AppErrorBoundary` logs its catch) and a WebGL context lost under a canvas still on the page to `POST /client-errors`, which writes one Warning under the `ClientErrors` category. It exists because SandPlayground sat on the error boundary for two weeks and nothing said so. The route is **outside `/api` on purpose**: it is fed by `navigator.sendBeacon`, which cannot carry the antiforgery header, so it is bounded by an 8 KB body, cleaned and truncated fields, and the `client-errors` rate limit instead. The script must stay above `consoleFilter.js` in `index.html`, so the filter wraps it and the audio-teardown noise is never reported. The page sends at most ten reports per load, one per distinct message.
- **One settings sheet (2026-10-01, user request; reverses the 2026-08-11 removal of `/settings`).** `Components/SettingsSheet.razor` is a `<dialog>` mounted once in `MainLayout` and opened by `SettingsService.RequestOpen()` from the top bar's account menu (and from the "App settings" button in Cabinet's and PoEcosystem's own panels). The gear stays out of the top bar (the 2026-07-13 call). It holds theme, mute, volume, haptics, reduce motion, colour-blind safe colours, the game-invite switch and the account's data export / erase (`AccountDataCard`, which erases and then reloads the app). Sound reaches every game because every engine rides `PoAudioBus`. Motion and colour ride `<html data-motion>` and `<html data-colorsafe>` (stamped pre-paint in `index.html`, kept live by `appPrefs.js`). **A game has no switch of its own for volume, mute, motion or colour-blind colours.** Cabinet and PoEcosystem each had one until the same day; either source turned the option on, so with the sheet's switch on the game's could not turn it off. Their stores now ignore the old keys (`pocabinet/settings.js` `sanitize`, `poecosystem/index.js` `paletteInUse` / `motionReduced`), so a value an older build saved cannot strand a player. A new engine reads `document.documentElement.dataset.motion === 'reduce'`, not `matchMedia` alone, or the sheet's switch does nothing in it. Key bindings, gamepad and anything specific to one game (race music, HUD size, graphics quality) stay in that game's own panel. The app's global reset zeroes `margin`, which un-centres every `<dialog>` and popover: give them `margin: auto` back. The numbered `--surface-*` tokens are translucent; an overlay wants `--color-surface`.
- **Game invites (2026-10-01, `Features/Invites`).** Two things: one Invite button in `LobbyPanel` and Cabinet's lobby (`Components/InviteLink.razor`: a popover holding the QR and a Share button; the link is always `/{game}/multi` because every lobby is the one shared room, and the QR is an SVG the server draws with QRCoder at `GET /api/invites/qr`), and Web Push to a past opponent from the profile's head-to-head list. **Pushes carry no payload.** A payload has to be encrypted to the subscription (RFC 8291); a bare wake-up needs only the VAPID JWT, which `WebPushSender` signs with the standard library. `js/pushWorker.js` (imported by BOTH service workers) answers the wake-up by fetching `/api/invites/pending` on the player's own cookie. The server writes every word and link of an invite from `InviteEndpoints.OnlineGames`; a caller only names a person and a game, the person must be an online opponent in the caller's own match history, and they must have switched invites on. **People are addressed by display name**, because that is all a `MatchHistory` row holds, so two players with one name share invites. The sender POSTs to an address a subscriber supplied, so `WebPushSender.IsAllowedEndpoint` (https, the four real push services) is checked on store and on send and redirects are off; loosening it is an SSRF. The VAPID key pair provisions itself into table `PushInvites` on first use, so there is no secret to create; losing the table only costs existing subscriptions. Chrome has no Push API in incognito, which includes a plain Playwright context: test with `launchPersistentContext`.
- **Server-timed results survive a recycle (2026-10-01).** `Infrastructure/VerifiedResultStore` (table `VerifiedResults`) is a write-through copy of the laps `PoRacerRaceRegistry` and `PoCabinetRaceRegistry` time themselves. The dictionaries stay the fast path; the store is read only on a miss. Before it, a score parked by `PendingScoreStore` across an F1 recycle was refused with 422 for good. It never throws, and rows are not swept (marked `ponytail:` in the file).

## Conventions and constraints

- **Never run the full suite after a change.** `scripts/test-all.ps1` and whole-tier `dotnet test` runs are off-limits unless the user explicitly asks. If a test run is warranted, run only the tests that cover the code you touched (`dotnet test <tier>.csproj --filter "FullyQualifiedName~<Thing>"`). The tiers are slow (E2EAPI ≈ 13 min) and the user prefers to run the full pass themselves. `dotnet build` is always fine — compile errors are not tests.

- **No Radzen.Blazor** (or similar heavy component libraries) — deliberately rejected for bundle size (~1.2 MB). Use native Blazor (`<Virtualize>`, plain CSS). Note that the external NET_RULES doc mandates Radzen; this repo's rejection overrides it — do not reintroduce the dependency to satisfy that rule.
- **Docs were rewritten in the 2026-08-18 cleanup.** `README.md` and `scripts/README.md` are now accurate summaries; `scripts/` holds working scripts only (the ~28 one-off debug files were deleted). The tree is still the truth when docs drift: trust `src/PoMiniGames.Client/Games/` and `src/PoMiniGames.API/Features/` over any doc table. There is no `docs/` tree and no `docs/build.mjs`; both went in b42fad4, so `README.md` plus this file are the written record for the platform. Per-game planning files also sit at the root and describe one game's build, not the repo: `SPEC.md`, `CAPABILITY-MAP.md`, `tasks/plan.md` and `tasks/todo.md` are PoJevArena's; `tasks/design.md` is PoCabinet's UI layout concepts.
- Source comments reference `AGENT.md` at the repo root, which houses the mandatory agent invariants.
- **`wwwroot/images/` is runtime-only, ~8 MB.** PoSports ships exactly 32 `atlas.json` + 32 `spritesheet.webp` pairs (4 characters x 8 animations), which is precisely what `js/posports/sprites.js` fetches. It was 170 MB until 2026-09-11: the per-frame `frames/**` export intermediates, the superseded `spritesheet.png` sheets, the capitalised `*-spritesheet/` source trees, and a whole `Mom` character cut from the roster back in f8fed70. They were retained "for re-export" by `scripts/posports-assets.ps1`, which had itself been deleted in b42fad4, so nothing could consume them. The three `<Content Remove>` rules that used to hide them from publish went too. Do not add a `Content Remove` rule to `PoMiniGamesClient.csproj` — everything under `wwwroot/` is published and precached deliberately now, so delete the unused asset instead.
- Theming is entirely token-driven: `wwwroot/css/app.css` `:root` defines the palette and a `prefers-color-scheme: light` block re-points only the surface/text/elevation tokens. Components must read colour through those variables, never raw hex, or they will be unthemed in light mode. Accent hues and per-game/canvas tokens are intentionally scheme-invariant.
- `style="..."` in `.razor` files is acceptable **only** to pass a runtime value into a CSS custom property (`style="--hp: @Percent%"`); the static rule still belongs in the scoped `.razor.css`.
- Default branch is `master`. Development is on Windows; repo scripts are PowerShell (`pwsh`).
- Comments in this codebase are dense and contract-oriented (audit/bug-fix annotations); match that style only when a real constraint needs recording.

## NET_AGENTS rules

These apply on top of the conventions above. They are intentionally short and absolute. See `AGENT.md` at the repo root for the full rule list.

- **Branch policy.** Work only on `master`. Use a different branch only if explicitly asked.
- **Restart + verify after a code change.** Rebuild and restart the API host (`dotnet run --project src/PoMiniGames.API/PoMiniGames.API.csproj`) after any code change and confirm it boots cleanly — a successful 200 from `GET /health` (or a "Now listening on" log line) is the bar. Do not report a change as done while the running instance is stale.
- **Read the docs first.** Before starting a task, check the repo root for a docs folder and skim it for the project summary. As of 2026-09-11 there is none — the old `docs/` tree was deleted in commit b42fad4 — so `README.md` plus this file are the summary, and `SPEC.md` is required reading before PoJevArena work. If a docs folder reappears, read it before touching code. Either way the tree under `src/PoMiniGames.Client/Games/` and `src/PoMiniGames.API/Features/` is the source of truth when docs drift.
- **No `dotnet user-secrets` for local config.** Put settings in `appsettings.json` (with `appsettings.Development.json` for local-only overrides) or Azure Key Vault. The previous standing exception is removed as of 2026-09-04.
- **Never push without an explicit ask.** Local commits and merges are fine; `git push` (to any remote) requires the user to say so first — the one standing exception is the `git sync` phrase below.
- **`git sync` is a standing push authorization.** When the user types `git sync`: stage and commit *everything* outstanding first (no leftover dirty tree), then push `master`. One commit, short subject, American slang, reads like a person wrote it.
- **Commit message style.** Keep commits short, casual, American-English, and human-sounding (e.g. "wires the kiosk reel into the post-match handler", not "Implement MarkFinished integration"). Avoid emoji, ticket IDs, and 50-word subject lines.
- **Don't hand the user commands to type.** If you can run it yourself (build, format, git, scripts, starting the host, clicking through a web GUI), run it. Only ask the user to type something when it genuinely needs their machine, their credentials, or their decision.
- **Targeted tests only.** Do not run all tests after code changes. Only run the tests related to the code change, or run no tests at all if the change is simple. Never run full test suites unprompted.
- **Treat warnings as errors.** Treat compile warnings as errors and make sure they are fixed.
- **Flag big deletions.** If a prompt removes more than 100 lines of code overall, say so in the reply.
- **Annotated UI screenshots.** After a UI change, take an annotated old-vs-new screenshot marking what changed, save the PNG under `SCREENSHOTS/` at the repo root with an HTML page next to it that shows it (a relative `<img>` to the PNG), and give the HTML page's full path.
- **TL;DR on long replies.** Any response longer than 100 words ends with a `**TL;DR** …` line of roughly 20 words.
