# CI blocks formatting drift within PoRacer; format locally before submitting changes.

Requires .NET SDK 10.0.400 (global.json) and Docker (Azurite + Testcontainers).

### What CI actually gates (`.github/workflows/deploy.yml`)

Only the **Unit** tier runs in CI — Integration/E2E need Azurite and Playwright and stay local via `test-all.ps1`. But the build job carries two further hard gates that are easy to trip without touching a test:

- **Trim audit**: the WASM client is published with `PublishTrimmed=true` + `EnableTrimAnalyzer`. Combined with `TreatWarningsAsErrors`, a single IL2xxx warning from new reflection-heavy code fails master. The host's own publish does not exercise this, so the analyzer only ever sees the client here. `src/PoMiniGames.Client/TrimmerRoots.xml` is the escape hatch.
- **WASM bundle-size budget**: the trimmed `_framework` output must stay ≤ 25 MB. The baseline was ≈ 20 MB, most of it the PoSurvive simulation engine shipping client-side; that game was removed on 2026-09-12, so measure before assuming the old figure.

The PoRacer format check is blocking; a missing `v*` tag at HEAD is a warning, not a failure (MinVer just stamps a pre-release). Deploy targets the `PoMiniGames` resource group and **discovers** the App Service name from it rather than hardcoding it — a resource rename can no longer silently 404 the deploy. It runs on F1, which cannot enable AlwaysOn, hence the prewarm loop before the smoke tests; `WEBSITE_RUN_FROM_PACKAGE=1` means the zip is mounted atomically.

## Test structure rules

- **100/50/25/25 rule**: *every* tier has its own ceiling — Unit 100, Integration 50, E2E-API 25, E2E-UI 25 — enforced by one shared assertion, `TierCeilingGuard` in `tests/Shared/`. Each tier declares a sealed, empty subclass of it naming its own ceiling (`TestCountCeilingTests`, `IntegrationTestCountCeilingTests`, `E2EApiTestCountCeilingTests`, `E2EUiTestCountCeilingTests`); the same reflection used to be copy-pasted into all four. It counts `[Fact]`/`[Theory]` **methods**, not discovered cases (`TheoryAttribute` derives from `FactAttribute`, so one probe catches both). When one trips, consolidate two facts into one theory or relocate to a cheaper tier — never raise the cap.
- Headroom is deliberately **not** recorded here. It rots on every commit, and the figure that used to sit in this line ("Unit 0 slots") was three audits stale and wrong in the alarming direction. Count it when you need it — `grep -rc "^\s*\[Fact\|^\s*\[Theory" tests/<tier> --include=*.cs`, minus one for that tier's own guard — or just run the guard test.
- All four ceilings are enforced by `scripts/test-ceilings.ps1` in CI without infrastructure. `test-all.ps1` reports discovered cases separately; TierCeilingGuard enforces method counts.
- Tiers, and there are exactly four: `PoMiniGames.Unit` (hermetic, no I/O) → `PoMiniGames.Integration` (Testcontainers Azurite) → `PoMiniGames.E2EAPI` (WebApplicationFactory HTTP contract) → `PoMiniGames.E2EUI` (Playwright; host runs under the "Test" environment). A fifth project, `tests/Shared` (`PoMiniGames.TestUtilities`), is a library the other four reference, not a tier.
- **There is no JavaScript test tier and no pre-commit hook.** This file used to describe a bUnit `PoMiniGames.Component` tier and a Vitest **SimJs** tier over `tests/PoEcosystem.Sim`, plus Husky.Net hooks running ESLint and Vitest on staged files. None of it exists — there is no `package.json`, no `vitest.config.js`, no `.husky/`, and no such test projects. The Component tier was retired 2026-09-11 (`scripts/test-all.ps1` still notes it) and the JS tooling went in b42fad4. Nothing runs on commit; run `dotnet format` yourself.
- **Any test that POSTs/PUTs/DELETEs `/api/*` must call `client.ArmAntiforgeryAsync()`** (`tests/Shared/AntiforgeryTestExtensions.cs`) or it gets a 403, not the status it asserts. Re-arm after a sign-in — the token is bound to identity claims. Antiforgery is deliberately NOT disabled for the Test environment.
- **`tests/Shared/TestBudgetGuard.cs` is the single source of truth for AI mocking.** Every fixture (Unit harness, Integration factory, E2E-API host, E2E-UI Kestrel host) applies `TestBudgetGuard.Overrides` before serving traffic, so the suite can never spend live tokens even when real keys sit in `appsettings.Development.json` or user-secrets. **Adding a new AI boundary means exactly one edit there** — the earlier inline-duplicated dictionaries drifted, which is how `IFaceAnalysisService` ended up unmocked.
- Without Docker, storage-backed tests fail with `connection refused (127.0.0.1:10002)`. That is the environment, not a regression — `docker compose up -d azurite` first. Integration/E2E tiers are slow (E2EAPI is ~13 min); prefer `--filter` while iterating.

## Architecture

Instant-play mini-games platform: .NET 10 Minimal API host that also serves the Blazor WebAssembly client (single origin, port 5080), with SignalR for real-time multiplayer and Azure Table Storage for persistence.

### Projects (`src/`)

- **PoMiniGames.API** — API host (assembly `PoMiniGames.API`, but `RootNamespace` is pinned to `PoMiniGames` — every file declares `namespace PoMiniGames.*` explicitly and new files must match). Vertical slice architecture: each feature lives in `Features/<Slice>` — Account, Auth, Diagnostics, Health, HighScores, Integrity, Leaderboard, MatchHistory, PoBrawl, PoCabinet, PoCoupleQuiz, PoEcosystem, PoFunQuiz, PoJevArena, PoJoker, PoMarbleRace, PoRacer, PoSports, PoVoxelStrike, Shared — containing its endpoints, hubs, and services. **Every HTTP route and SignalR hub is registered in exactly one place**: `Infrastructure/EndpointRouteExtensions.MapPoMiniGamesEndpoints()`. Auth is applied at the route-group boundary — leaderboard reads are anonymous, all game-data writes require auth; rate limits are declared per slice (policy names: `highscores`, `leaderboard-read`, `play-session`, `account-data`, `ai-generation`, `pocabinet`, `pojevarena`, `pojevarena-decide`, in `Infrastructure/RateLimitingExtensions`). The list used to name `infer` and `face-analysis`: `infer` guarded PoSurvive's relay and was deleted unused on 2026-09-13, and `face-analysis` never existed here at all — `IFaceAnalysisService` survives only in comments.
- **The `/api` prefix is declared once**, on the authenticated group: `app.MapGroup("/api").RequireAuthorization()`, with each slice mounting a *relative* group under it (`MapGroup("/joker")`, `MapGroup("/matches")`, …). It was `MapGroup("")` until 2026-09-11, with twenty-odd slice groups each repeating the literal `/api` — which hid the fact that this boundary is exactly the scope `AntiforgeryExtensions` validates. The anonymous surfaces (`MapGetLeaderboard`, `MapUnifiedLeaderboardEndpoints`, `MapPoVoxelStrikeAssetEndpoints`, `MapIntegrityStatusEndpoint`, and the platform/health/diag endpoints) are mapped on `app`, **not** on the group, so they still spell their full `/api/...` path. Getting that backwards silently relocates a route to the site root — `PlayerStatsEndpoints.MapGetLeaderboard` carries a comment saying so, because it is the one method in that file that differs from its three siblings.
- **PoEcosystem got its API slice on 2026-09-14** (`Features/PoEcosystem`): three cloud world slots per identity, a public gallery, a decade chronicle and cloud thoughts. A world is an opaque gzip'd snapshot the browser engine packs itself (`js/poecosystem/sim/persistence/codec.js`, typed arrays as tagged base64) — the server stores bytes in blob container `poecosystem-worlds` and metadata in table `PoEcosystemWorlds` (partition = hash of the claim id; sharing mirrors a row into the `public` partition keyed by an 8-char code, so the gallery is one partition query). `EcosystemWorldStore` degrades to empty/null on storage failure. Do **not** put `.Accepts("application/gzip")` on the PUT: `IAcceptsMetadata` takes part in endpoint *selection*, so a mismatched Content-Type lands on a synthetic 415 endpoint with no auth metadata and an anonymous caller gets the antiforgery 403 instead of 401 (a route-exists leak the E2E-API contract test catches). AI game key `ecosystem` (own resilience partition) plus task key `ecosystem.thought` (cheap model); `PoEcosystem:Features:UseMockAI` is in `TestBudgetGuard`. Cloud thoughts are throttled to one per 20 s in `thoughtBridge.js` and capped per session in the viewer, because each spends the caller's daily allowance. Engine-side, the same commit made the render frame stride 13 (five base traits ride along for the evolution tint), added `sim/creatures/lineage.js` (family trees, watch-list, player naming — all snapshotted) and `sim/behavior/tech.js` (the tribe's Camp → Fire → Palisade → Farming → Watchtower ladder, deterministic, no RNG draws), and `render/director.js` + `render/pip.js` (auto-director camera; Document Picture-in-Picture with a 2D mirror canvas, video PiP fallback). The snapshot round-trip divergence noted at the time (~115 ticks after restore) was fixed on 2026-09-23 — see the observation note below. The GFX pass that followed lives in `render/sky.js` (dome + clouds, camera-parented) and `render/materials.js` (`enhanceLambert`: one `onBeforeCompile` hook for rim light, world-space mottle and wind sway, shared by creatures, flora and props; `materialClock`/`materialDetail` are the only uniforms the renderer drives). Keep MeshLambertMaterial — the flat-shaded low-poly look is the art direction, and Lambert has lit per fragment since three r155, which is what the injected bump normals rely on. Shader chunk names (`opaque_fragment`, `normal_fragment_begin`) are pinned to three 0.165.0 in the import map; bumping three means re-checking them.

- **PoCabinet** (third-person arcade racer — the cockpit view and `cockpit.js` are gone; modes are 1player / multi / demo only, since 2P was removed 2026-09-29 and a stale `/2player` link plays 1P; always daytime, so every night-only effect was deleted, not idled; `Features/PoCabinet`, `Games/PoCabinet`, `js/pocabinet/`). Track geometry lives once, in `Shared/Games/PoCabinetTrackGeometry` (knots, width, atmosphere): the server sim, the in-browser solo race, the scene and the minimap all resample the same knots. Until 2026-09-23 the client drew ellipses while the server simulated splines, the server sim never moved a car, and nothing ever created a multiplayer race. Physics is **two mirrored implementations**: `PoCabinetTrack` / `PoCabinetPhysics` / `PoCabinetAiDriver` (C#) and `track.js` / `physics.js` (JS), with the same constants in the same operation order. Solo races run the JS copy. Multiplayer runs the C# copy on the server while the browser predicts its own car with the JS copy, replaying the inputs the server has not acknowledged yet (`PoCabinetInput.Seq` → `PoCabinetCarState.AckSeq`). A change to one side must land on the other: a scratch trajectory diff (C# console vs node, 5 cars with contacts) agreed to 1e-8 over 1,200 ticks when they were written. `race.js` owns the frame loop (fixed 30 Hz ticks, render interpolation, remote cars drawn 100 ms behind, recording for the `telemetry.js` chart, replay and the MediaRecorder lap clip); the page is only the HUD. Driver aids and keyboard/gamepad/touch/tilt input (`input.js`) shape the input only, so online they need no server support. There is **one lobby and no join codes** (2026-09-29): the first arrival at `/pocabinet/multi` hosts (track + AI stepper), the next take seats up to 8, and anyone arriving mid-race (or at 8) waits in the lobby group with a null seat, can Watch (spectate), and is re-seated on the next `LobbyState`. Seats key on claim identity (reconnect-safe), AI officials fill free seats, and the lobby reopens with the same roster after a race (that is the rematch). The race and its groups use the fixed internal id `PoCabinetLobbyService.RaceId`. The per-tick snapshot has a 2 KB budget at 8 cars (E2E-API contract), so don't add a per-car field without taking one out. The GFX/sound layer (2026-09-23) is render/audio-only and derives everything from poses the client already draws, so it needs no snapshot field and never touches either physics copy: `postfx.js` (one pass: speed blur, lens rain, flash/slow-mo grade), `sky.js`, `scenery.js` (landmarks, lamps, start gantry, press-pen flashbulbs; seeded per track id), `kerbs.js` (apex kerbs are feel only — buzz, shake, rumble, no grip change), `fx.js` (smoke, sparks, persistent skid marks), and a synthesized `audio.js` (V8 PeriodicWave engine on a virtual gearbox, HRTF rival engines with Doppler). `scene.fx` is the per-frame bag race.js/environment.js write into. The photo-finish slow motion scales how much time feeds race.js's fixed-tick accumulator, solo only — lap times stay on the sim clock. `PoCabinetPage.razor.css` also styles the child components (lobby, selectors, settings, dialogue bubble), so those rules must be `::deep` or they silently never apply. **Stored lap times are server-computed (2026-09-29).** A solo submit carries `Inputs`, the player's per-tick controls (quantized to thousandths in `race.js` *before* they are stepped, packed as base64 little-endian int16 triples), and `PoCabinetLapVerifier` re-runs the whole solo race (player in grid slot 2, the four officials, contacts) and stores the lap *it* times; the claimed time is only compared and logged. That makes `PoCabinetLapVerifier.Replay` a third mirror of `race.js` `soloTick`: a change to the solo grid, the clock arithmetic, the AI or the lap bookkeeping must land there too. Multiplayer submits carry no proof; the registry keeps each human's server-timed best lap for an hour (`TakeVerifiedLap`, one use, in memory). A submit with neither gets 422. `tests/Shared/Fixtures/pocabinet-lap-proofs.txt` holds browser-engine proofs with the JS-timed lap (JS and .NET agreed to within 2.4e-9 s through walls and contacts); regenerate them, never hand-edit, if either physics copy changes on purpose. It proves a lap is physically possible, not that a human drove it. GFX/sound pass 2 (2026-09-29) is render/audio-only too: `music.js` (adaptive synthesized score on audio.js's bus; layers follow battle proximity and the final lap; `music` setting), exhaust flames from `audio.takePops()`, cosmetic per-car dents (`cars.js` `addDamage`, one shared-program paint hook), wet-road light streaks (`reflections.js`), a grandstand crowd (`scenery.js`; positional murmur and cheers) and a glass gauge whose speed/gear spans race.js writes directly. Those spans are rendered empty so Blazor owns no text node in them, and sibling `@key`s in the race section must not collide (the countdown keys on its bare number). **UI/AI consolidation (2026-09-29):** one start card (Solo/Online/Demo switcher; the campaign lives on the track cards — a "locked" stage only means the race doesn't count yet, so every track stays raceable), a compact HUD strip (speed and place live on the gauge and badge), results in a non-modal `<dialog>` with pinned actions and one Share menu, and pause as a `showModal()` dialog whose own Esc-close is cancelled because Esc is `input.js`'s pause toggle. The canvas height is `--pocabinet-canvas-h` (viewport minus header and strip); touch controls, the gauge and the results key off it. Render quality and FOV are no longer settings: `scene.js` steps quality down on a sustained dip under 45 fps. Sector splits come from `race.js` (`OnSectorAsync`, crossings interpolated inside the tick), not from the page. `PoCabinetUiSettings` round-trips through `PoCabinetJsonContext`, so a C# property name is its JS key. **AI:** `PoCabinetAiService` writes the officials' per-track banter pool (`GET /api/pocabinet/banter`, one structured call per track per day, shared by every player — that cache is the pre-bake) and the post-race debrief (`POST /api/pocabinet/debrief`, numbers from `telemetry.js` `debriefFacts`, server-written prompt). This reverses the original scripted-only decision on user request. - **PoJevArena** (2026-09-25; `Features/PoJevArena`, `Games/PoJevArena`, `js/pojevarena/`, spec in `SPEC.md`). A 10v10 creature battle where every tactical decision comes from TypeSafe's **Jev** (OpenRouter, `POST {Endpoint}systemone`, model pinned to `typesafe/jev-1.13`). Jev is **required, with no decision fallback anywhere real**: no key → `status.configured=false` and Deploy is disabled; a failed or late call makes the unit hold its last intent indefinitely (the user's call). `StubJevClient` exists for the test hosts only — `PoMiniGames:Jev:UseStub` is honoured solely under the `Test` environment (stricter than `AiMockFallback`, which also allows Development) and is the one `TestBudgetGuard` line. The key is Key Vault `PoMiniGames--Jev--ApiKey` (conditional secret back in `infra/kv-secrets.bicep`; the vault secret itself survived the 2026-09-23 "drop the jev leftovers" commit, so dev and prod already have one). **The server writes every word Jev sees**: the browser sends only numbers and catalog ids, the unit's creature (names included) is resolved from the server-held match roster, and `JevPromptBuilder` builds the state and question set — so the proxy can't be used as a free Jev pass-through. Its output is pinned by Verify snapshots (`*.verified.txt`); a wording change is a behaviour change for the model and must show up as a reviewed diff. The daily cap (20k calls/identity) is a second `AiTokenBudget` counting calls over table `PoJevArenaCallLedger`, flushed by a second `AiTokenBudgetFlushService` registered via `AddSingleton<IHostedService>` — `AddHostedService<T>` is a TryAddEnumerable and silently drops a second instance of the same type. The ability registry (`PoJevArenaCatalog.Abilities` in `Shared/Games/PoJevArenaShared.cs`) is the extension point: adding an ability is that row + one handler in `abilities.js` + one visual in `fx.js`, and nothing else names abilities. Every creature melees; an 80-point build budget bounds stats + abilities; creatures fight on **battle HP = designed HP / 5** (`PoJevArenaRules.BattleHp`, mirrored by `sim.js` `battleHp`; the user's call 2026-09-30). Designed HP (50–500) is still what the budget prices and the library stores, but everything a player or Jev reads — factory slider, cards, inspectors, the prompt's `HP: x/y` — is battle HP, and the prompt builder validates the reported HP against it, so the two rules must change together. `DAMAGE_SCALE` stays 0.5; scripted headless matches run 12–21 s and a real-Jev match ~50 s (was ~2:40). Engine: `sim.js` is pure and node-runnable, `scheduler.js` runs on *sim* time (hidden tab = no calls), `blackbox.js` records every frame for the scrubber, `debrief.js` turns its decision log into the end-of-match "what each team was thinking" summary (numbers only; `JevDebrief.razor` owns the wording, and a debrief runner-up is the best option Jev did *not* pick, because its pick is not always the argmax), and the page's only road to the server is `[JSInvokable] DecideAsync` (so every call rides the antiforgery/credentials `HttpClient`). Two test-harness facts found building it: the Integration factory's storage override lands after the host binds `TableServiceClient`, so Integration tests write to the developer's **local Azurite** (the library test deletes what it creates for that reason); and the E2E-API fixture registers no header FakeAuth at startup, so signed-in E2E-API rows sign in through `/auth/login/fake` instead. Under `?autoGuest=1` the play-session mint 403s once on every game page (token predates the guest identity) — known, tolerated, not the page's. **2026-09-30 pass (SPEC §15):** three seeded hazard maps (`sim.js` `ARENAS`: pillars, brush, tar) and a fourth base option `take_cover`, so every `tactical_action` snapshot carries it and the state has `coverDistanceM`/`inBrush`/`inTar` (validated server-side; -1 means no pillars). Creature Elo + careers ride the existing result report as increments; the result body is still the client's word, only clamped. Sound (`audio.js`) rides `PoAudioBus`'s sfx bus and music is `PoMusicDirector.tension` — no own AudioContext, no own mute. `postfx.js` is an optional WebGL2 grade over the 2D canvas: the 2D canvas stays the input and pointer target (`is-composited` makes it transparent, never hidden), and it must stay first in DOM so glassFx's largest-canvas pick samples it, not the GL canvas. The whistle now plays a kill cam + ceremony (~7 s, skippable, skipped under reduced motion) *before* `OnMatchEnded`, so anything waiting on the result waits for that too. The Black Box floor keeps its stains across scrubs (it is the whole match's record). Blazor renders a `bool` attribute as present/absent, so `aria-pressed` goes through the page's `Pressed()` helper. **Locomotion is force-based** (2026-09-30, `sim.js` `integrate`): no per-tick damping and no velocity is ever set directly. Legs push toward the wanted velocity, capped by grip (μ·m·g, g = 9.81, masses 24–120 kg) and by leg power (P/v); unfooted bodies (reeling, shelled) skid on kinetic friction; air drag and tar resist. Leg work drains a critical-power/W′ energy reserve (cruise ≈ sustainable, sprint and bursts spend it, empty = 40% power and no sprint), reported to Jev as `Stamina` (-1 = not reported, so older snapshots are unchanged) and drawn under the HP bar. Lunges and dodges are explosive pushes, not velocity kicks. Boulders fly a real ballistic arc (`arcHeight`): they sail over bodies mid-flight and land where aimed. Every non-DoT blow shoves its victim (impulse ÷ effective mass, closing speed cancelled, a stagger that suppresses steering and new swings); colliders are 1.15× the drawn body radius and contacts relax over 3 passes. The live battle is full screen: the team columns and HUD pill only show while Tab is held (engine `OnStats`) or the Stats button is on. The debrief ends with one story per unit (`debrief.js` `story`, worded in `UnitStories.razor`).
- **PoMarbleRace** (`Features/PoMarbleRace`, `Games/PoMarbleRace`, `js/pomarblerace/`). **Board totals are server-recomputed (2026-09-30):** a submit carries the run's races (place, finish time, lead over 2nd) and `MarbleRaceRunVerifier` re-adds them and stores *its* total (422 if it can't: a non-top-10 race, an unknown map, or a finish faster than the course at 2× `MAX_SPEED`). ### Cross-cutting facts

- Auth: Microsoft Entra (MSAL) with a BFF cookie pattern (`BffAuthenticationStateProvider`, encrypted cookies via Data Protection), plus a dev-only DevAuth bypass and guest login. Client gates most pages on auth.
- CSRF: `Infrastructure/AntiforgeryExtensions` validates a synchroniser token on every POST/PUT/PATCH/DELETE under `/api/*`. Scope is exact and load-bearing — SignalR hubs live at their own roots (`/poracer/lobby-hub`, …) so their POST `/negotiate` stays ungated, because the SignalR client cannot be taught to attach the header. `app.UseAntiforgery()` alone would NOT cover this app: since .NET 8 it auto-validates only form-bound endpoints, and every endpoint here takes JSON.
- The client `HttpClient` is an explicit four-deep handler pipeline built in `Client/Program.cs`, and **the order is a contract**: `TransientRetryHandler → AntiforgeryHandler → IncludeCredentialsHandler → HttpClientHandler`. Retry is outermost so every replayed clone re-enters `IncludeCredentialsHandler` and gets its credentials mode re-applied before hitting the browser transport; `AntiforgeryHandler` sits directly above `IncludeCredentialsHandler` because its token fetch must carry the cookie the server pairs the header against. A `window.fetch` patch (`js/crossOriginFetchPatch.js`) is a belt-and-braces duplicate of the credentials behaviour, scoped to the API origin only — a blanket patch previously broke MSAL sign-in.
- **AI (Azure AI Foundry)** — `src/PoMiniGames.API/AI/`, ~20 files, the most expensive thing to get wrong. One `PoMiniGames:AI` binding replaced the old per-game `*:AzureOpenAI:*` sections, resolved from Key Vault (`PoMiniGames--AI--FoundryEndpoint`, `--DefaultDeployment`, `--Deployments`). Chat clients compose as decorators: `BudgetedChatClient` → `ResilientChatClient` → `InstrumentedChatClient`. Spend is bounded by a per-identity daily ceiling (`TokenBudget:DailyTokensPerIdentity`, 250k), because a rate limit shapes burst but bounds no spend — one tab left open is ~36k calls/hour. (The `infer` policy that used to make this point is itself gone; `ai-generation` is the one that now fronts a model call.) `ValidateDeploymentsOnStartup` lists the account's real deployments and fails Production boot on a name that isn't there; that check exists because `gpt-4o-mini`/`gpt-4o` were configured for months and never existed on the shared account (real names: `gpt-5.4-nano`, `gpt-5-nano`, `gpt-5.4-mini`, `Phi-4-mini-instruct`, `Phi-4`). `AIFoundryOptions.Deployments` must stay a **plain settable `Dictionary`** — the configuration binder does not populate an `IDictionary` property through the indexer, and the silent failure was every game running on the default deployment while the status endpoint reported a different answer.
- **Concurrency is two-level, and the global level is the load-bearing one.** `AiConcurrencyGate` is a single `ConcurrencyLimiter` (2 permits) shared by every resilience pipeline; each pipeline *also* has its own small limiter for per-game fairness. Do not go back to one `AddConcurrencyLimiter` per pipeline: that builds a separate limiter each time, so the five registered pipelines permitted 10 concurrent calls against an account measured to serve one or two (`x-ratelimit-limit-requests: 1`). `GlobalQueueLimit` is computed from the partition count and must stay ≥ the sum of the per-game permits, or a call that won its game's permit gets rejected at the gate and the circuit breaker counts a healthy account as failing.
- **The token budget is durable.** `AiTokenBudget` is a write-behind cache over `IAiTokenLedgerStore` (Table `AiTokenLedger`, PartitionKey = UTC day, RowKey = identity hash), flushed every 30 s by `AiTokenBudgetFlushService` and once more on graceful shutdown. It was process-local, which on F1 (no AlwaysOn, so idle = recycle) made "250k per identity per day" mean "per identity per uptime". Writes are **increments under an ETag**, never absolutes — same reasoning as the PoBrawl demo Elo board. Call `CheckAsync`, not `Check`: only the async path hydrates an identity's durable total.
- **HybridCache has a real L2.** `TableDistributedCache` (Table `PoMiniGamesCache`, SHA-256 row keys, payload chunked across 64 KiB properties) is registered as `IDistributedCache` *before* `AddHybridCache()`. Without it the "L1/L2" was L1 only and every cached generation was re-bought after each recycle. It never throws — every failure degrades to a miss — and a failed table create is remembered for 10 s so a storage-down host does not pay the client's network timeout on every cache read.
- **Two providers, one SDK surface.** `PoMiniGames:AI:Provider` selects `azure` (Managed Identity) or `openai` (any OpenAI-compatible endpoint + `ApiKey`) — the latter reaches Ollama (`http://localhost:11434/v1`, free local dev) and Gemini's compatibility endpoint (cheaper per token, separate quota). Empty infers from the endpoint host, so existing Key Vault config keeps resolving to Azure. Both paths hand back the same `OpenAI.Chat.ChatClient`, so every decorator, the options cache and the capability table apply unchanged. `FoundryDeploymentValidator` skips non-Azure providers — it lists deployments from the Azure data plane and has nothing to call elsewhere. Pair a new provider with `ModelCapabilityOverrides`: the capability heuristic reads deployment names, and a local model's name rarely says what wire fields it accepts.
- **PoJoker is one model call per joke, not two.** The punchline prediction and the rating are a single structured reply (`VerdictSchema`, `punchline` declared first so it streams first), cached 24 h on the joke's content hash. Two concurrent calls against a 1-request account meant the second reliably ate a 429 plus a retry. The cost is that `joker.rating`'s cheap-deployment task key no longer applies to this path; round trips are the scarce resource here, not tokens. `QuizPrebakeService` (`PoMiniGames:AI:QuizPrebake:Enabled`, **off by default**) warms the PoFunQuiz question cache off-peak — it is the one background job that deliberately spends money, so it never switches itself on.
- **PoSurvive is gone (2026-09-12).** The game, its API slice (`Features/PoSurvive`: the `/api/infer` relay and `/api/evolution/*`), the `Inference:*` and `Simulation:*` configuration on both sides, the simulation engine in `Application`/`Shared`/`Domain` (`Application` has since been dissolved entirely — see above), the `survive` AI deployment key and its resilience partition, the `EvolutionRecords` table registration, and ~2 MB of `wwwroot` assets all went with it. `InferenceHealthTracker` stayed — it is general AI telemetry now, still in `PoMiniGames.Shared.Simulation.Models` because moving it would ripple through every chat-client decorator. The client takes `PoMiniGames.Domain` directly for the leaderboard row types.
- **Game routes are the uniform `/{game}/{mode}` scheme, with no aliases.** Modes are `1player` / `2player` / `multi` / `demo` (`GameModes.ToSlug`). The duplicate `@page` aliases were deleted on 2026-09-11 — `/funquiz/multiplayer` and `/{couplequiz,poracer,posports,povoxelstrike}/lobby` — and the matching `"multiplayer"` / `"lobby"` segments came out of `GameModes.Parse` with them. That pairing is load-bearing: three of those games also declare a `/{game}/{Mode}` catch-all, which would otherwise have swallowed the stale URL and parsed it as Multiplayer on a page that cannot host it. Unrecognised segments read as `OnePlayer`, which is what `Parse` already documented. Query-string legacy forms (`?mode=2p`, `?demo=1`) and the `2p`/`2ps`/`1` segments are still accepted — `2ps` in particular still drives PoFunQuiz split-screen.
- **PWA / offline resilience.** `service-worker.js` + `service-worker.published.js`, `manifest.webmanifest`, with `OnlineStatusService` (offline banner) and `AppUpdateService` (new-version prompt) initialized once from `MainLayout`. Score submission is durable: `PendingScoreStore` (localStorage queue) → `ScoreSyncService` (flusher) → `GameResultService`. A failed leaderboard submit is parked, not lost. This is also why anonymous leaderboard *reads* never became anonymous writes — guests park scores locally and flush them on sign-in.
- `GET /health` serves two audiences by `Accept`: `text/html` returns the Blazor shell so `Pages/HealthPage.razor` renders the human status page; anything else (monitors, `HttpClient`, the deploy smoke tests) keeps the legacy JSON report. Content negotiation exists because server routes match ahead of `MapFallbackToFile`, so a Blazor `@page "/health"` would otherwise be permanently shadowed. `/api/health/*` is the canonical JSON surface; `/api/diag` is the developer configuration dump (JSON-only — the Blazor `/diag` page was deliberately removed 2026-08-07 because it shipped 505 lines of developer chrome in every player's WASM bundle and only rendered JSON the API endpoints already expose).

It was a dev-only demo surface for the external img2threejs pipeline: `/api/diag/gallery` and `/api/gallery/upload` 404'd outside Development, but `Pages/PoGallery.razor` and 1.1 MB of models under `wwwroot/games/pogallery/` shipped to every player regardless. Slice, page, model, assets and footer link all went together.
- Storage tables are created automatically on startup; dev uses `UseDevelopmentStorage=true` against Azurite, production uses Managed Identity. Application Insights is intentionally NOT configured in local dev (`PoMiniGames:ApplicationInsights:ConnectionString` empty by design): the connection string is treated as a Key Vault secret, never committed, and `/api/diag` reports `applicationInsightsConfigured: not-configured`. Local telemetry goes to console / Serilog only; trace a session locally with logs + the existing health snapshot.

## NET_AGENTS rules

These apply on top of the conventions above. They are intentionally short and absolute. See `AGENT.md` at the repo root for the full rule list.

- **Branch policy.** Work only on `master`. Use a different branch only if explicitly asked.
- **Restart + verify after a code change.** Rebuild and restart the API host (`dotnet run --project src/PoMiniGames.API/PoMiniGames.API.csproj`) after any code change and confirm it boots cleanly — a successful 200 from `GET /health` (or a "Now listening on" log line) is the bar. Do not report a change as done while the running instance is stale.
- **Read the docs first.** Before starting a task, check the repo root for a docs folder and skim it for the project summary. As of 2026-09-11 there is none — the old `docs/` tree was deleted in commit b42fad4 — so `README.md` plus this file are the summary. If a docs folder reappears, read it before touching code. Either way the tree under `src/PoMiniGames.Client/Games/` and `src/PoMiniGames.API/Features/` is the source of truth when docs drift.
- **No `dotnet user-secrets` for local config.** Put settings in `appsettings.json` (with `appsettings.Development.json` for local-only overrides) or Azure Key Vault. The previous standing exception is removed as of 2026-09-04.
- **Never push without an explicit ask.** Local commits and merges are fine; `git push` (to any remote) requires the user to say so first — the one standing exception is the `git sync` phrase below.
- **`git sync` is a standing push authorization.** When the user types `git sync`: stage and commit *everything* outstanding first (no leftover dirty tree), then push `master`. One commit, short subject, American slang, reads like a person wrote it.
- **Commit message style.** Keep commits short, casual, American-English, and human-sounding (e.g. "wires the kiosk reel into the post-match handler", not "Implement MarkFinished integration"). Avoid emoji, ticket IDs, and 50-word subject lines.
- **Don't hand the user commands to type.** If you can run it yourself (build, format, git, scripts, starting the host, clicking through a web GUI), run it. Only ask the user to type something when it genuinely needs their machine, their credentials, or their decision.
- **Targeted tests only.** Do not run all tests after code changes. Only run the tests related to the code change, or run no tests at all if the change is simple. Never run full test suites unprompted.
- **Treat warnings as errors.** Treat compile warnings as errors and make sure they are fixed.
- **Flag big deletions.** If a prompt removes more than 100 lines of code overall, say so in the reply.
- **Annotated UI screenshots.** After a UI change, take an annotated old-vs-new screenshot marking what changed, save it under `SCREENSHOTS/` at the repo root, and give its full path.
- **TL;DR on long replies.** Any response longer than 100 words ends with a `**TL;DR** …` line of roughly 20 words.


### PoRacer cleanup contract

- `js/poracer/index.js` explicitly owns input, Canvas rendering, interpolation and WebGL composition. Start/stop release listeners, animation frames, GPU resources and cached bitmaps.
- `PoRacerRaceRegistry` owns separate solo, demo and multiplayer races. Multiplayer rounds get unique codes; claim-derived identities bind lobby seats to race connections. Snapshots identify the local car only in the join response.
- Leaderboards rank best completed laps. `PoRacerScoreDto.BestLapSeconds` retains the JSON name `totalTimeSeconds`, and Azure retains its `TotalTimeSeconds` column. Existing values are preserved, not multiplied or divided to infer old race semantics.
- Score writes use the shared highscore rate limiter; reads use `/api/leaderboards/poracer`. Retryable writes persist through `PendingScoreStore` using source-generated serialization metadata.
- Test caps count methods, not theory rows. No fifth test tier is introduced.
